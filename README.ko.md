# SmartThink

**[Claude Code](https://docs.anthropic.com/en/docs/claude-code)를 위한 컨텍스트 무장 엔진.**

SmartThink는 질문에 답하지 않는다. 답할 세션을 만든다.

본 작업을 시작하기 전에 의도적으로 토큰을 써서, 이 세션을 그 작업에 특화된 전문가로 만든다.
파인튜닝이 아니라 인컨텍스트 무장이며 세션 안에서만 산다. 무장이 끝나면 브리핑을 출력하고
턴을 종료한다. 작업 지시는 사용자가 한다.

```
/st 사내 문서 검색 도구를 새로 만들지 기존 것을 개선할지 결정
```

---

## 무엇이 다른가

사고 프레임워크 도구는 대개 요약본을 준다. SmartThink는 **원문**을 싣는다.

- **요약이 아니라 원문 강화판.** 선택한 레퍼런스 모듈은 한 글자도 바뀌지 않은 채 팩에 들어가고,
  SHA-256 계약이 그것을 증명한다. 그 위에 작업 적용 레이어와 리서치 합성이 얹힌다. 팩은 원문을
  압축한 것이 아니라 증폭한 것이다.
- **전부가 아니라 라우팅.** 레퍼런스 9개는 다 합쳐 약 200K 토큰이다. 전부 로딩하는 것은 무장이
  아니라 익사다. Cynefin 진단과 분류 트리가 후보 5개를 뽑고 3개에 ★를 붙이며, 무엇을 읽기
  전에 게이트에서 사용자가 승인한다.
- **리서치는 무장 이후.** 레퍼런스를 먼저 읽으므로 검색 쿼리를 짜는 쪽이 이미 어떤 프레임에
  무엇을 먹일지 안다. 검색 원문 페이지는 서브에이전트 창에서 소화되고 메인에 들어오지 않는다.
- **브리핑에서 턴이 끝난다.** 무장은 결론이 아니라 결론을 낼 준비다. 여기서 멈추는 것이
  사용자가 방향을 고칠 마지막 싼 순간이다.

## 설치

플러그인이 정식 경로다.

```bash
# 마켓플레이스에서
/plugin marketplace add Bkankim/bkankim-plugins
/plugin install smartthink

# 또는 로컬 클론에서 바로
git clone https://github.com/Bkankim/smartthink.git
claude --plugin-dir ./smartthink
```

> **설치 후 호출 이름을 직접 확인하라.** Claude Code 버전과 플러그인 로딩 방식에 따라 스킬이
> `/smartthink`로 열릴 수도, 네임스페이스가 붙은 형태로 열릴 수도 있다. `/skills`를 실행해
> 목록에 뜬 이름을 쓰면 된다. 여기서 단정하지 않는다.

### 대안: `install.sh`

플러그인 시스템을 쓰고 싶지 않거나, 네임스페이스 없는 짧은 `/st` 명령을 원하면 설치
스크립트를 쓴다. `~/.claude/` 아래로 심링크를 건다.

```bash
git clone https://github.com/Bkankim/smartthink.git
cd smartthink
./install.sh
```

스킬 1개(`smartthink`), 에이전트 정의 2개(`st-thinker`, `st-armorer`), `/st` 명령 별칭을
설치하고 `~/.claude/smartthink-vault/`에 빈 vault를 시드한다(`SMARTTHINK_VAULT`로 변경 가능).
v2에서 올라오는 경우 v3에서 삭제된 에이전트 정의를 가리키던 심링크도 함께 정리한다.

**설치 후에는 새 Claude Code 세션을 열어라.** 기존 세션은 새 스킬·에이전트를 인식하지 않는다.

## 사용법

### 서브커맨드

**첫 토큰이 정확히 일치할 때만** 인식한다. `/st status page 재설계`는 `status` 서브커맨드가
아니라 주제다.

| 서브커맨드 | 하는 일 |
|---|---|
| `/st init` | 로컬 사전 스캔 + 짧은 6문 인터뷰로 프로필을 각인한다. 멱등이며 기존 프로필이 있으면 갱신 모드 |
| `/st retain` | 이번 세션에서 실제로 판단을 바꾼 프레임을 추론해 라우팅·인사이트·프로필 델타를 제안하고, 승인된 것만 기록한다 |
| `/st status` | 프로필 요약, 최근 팩, 진화 카운트, 환경 진단. 읽기 전용 |

### 플래그

| 플래그 | 하는 일 | 언제 쓸모 있나 |
|---|---|---|
| `--digest` | 팩의 레퍼런스 원문 절을 모듈별 증류본으로 대체(총 10~20K) | 프레임은 필요한데 이 작업에 100K 컨텍스트를 내줄 수 없을 때 |
| `--report` | 팩을 `st-thinker`에 넘겨 분석 보고서를 받는다 | 세션 무장이 아니라 결론을 대신 써주길 원할 때 |
| `--lite` | 레퍼런스·팩·게이트 없이 Cynefin + 제1원리 인컨텍스트 분석 | 주제를 빠르게 훑을 때, 또는 서브에이전트가 없는 환경 |
| `--nosearch` | 리서치 생략, 팩 3절 없음 | 이미 아는 도메인이거나 검색 대기가 아까울 때 |
| `--budget N` | 게이트 상한을 N토큰으로 고정하고 절삭 순서를 적용 | 남은 세션에 컨텍스트가 얼마나 필요한지 아는 경우 |
| `--pack <경로>` | 기존 팩을 재장전하고 게이트를 생략 | 한 번 무장했던 작업을 새 세션에서 이어갈 때 |

**주제는 서브커맨드와 플래그를 걷어낸 나머지 텍스트다.** 레거시 접두어(`agent`, `light`,
`search`)는 v3에서 폐지되어 이제 주제의 일부로 읽힌다.

## 동작 흐름

```
  능력 감지            Agent 도구가 있는가 -> armorer 경로, 없으면 인라인 경로
       |
  프로필 + 진화 상태    vault에 있으면 읽는다
       |
  Cynefin 진단         명확(Clear) 도메인이면 짧게 답하고 종료. 무장하지 않는다
       |
  모듈 추천            후보 5개, ★ 3개. 라우팅 가중치 반영
       |
  === 게이트 ===       해석·진단·모듈·예상 비용·리서치 상태를 표시
       |               모듈 조정, 예산 지정, 리서치 끄기가 여기서 가능
  무장                 레퍼런스 로딩 -> 리서치 -> 합성 -> 팩 Write
       |
  브리핑               팩 1절을 그대로 출력
       |
  턴 종료              사용자가 작업을 지시한다
```

**게이트가 이 도구의 핵심 UX다.** 비싼 커밋 직전의 마지막 싼 순간이고, 지불하기 전에 청구서를
보여준다.

```
━━ SmartThink 무장 게이트 ━━

1. 입력 해석
   사내 문서 검색 도구를 새로 만들지 기존 것을 개선할지 결정한다.
   판단 대상은 빌드 대 개선이며, 성공 기준은 아직 미확정이다.

2. 진단
   Cynefin: Complicated  |  분류: 의사 결정

3. 추천 모듈 (5개, ★ = 주력)
   ★ 인지 무기고     - 매몰 비용과 가용성 편향이 "새로 짓자"를 부풀리는 지점을 짚는다
   ★ 실행 속도       - 되돌릴 수 있는 결정과 없는 결정을 갈라 판단 속도를 정한다
   ★ 안티프래질 전략 - 기존 개선을 기본값으로 두고 신규 구축을 작은 옵션으로 사는 바벨 배치
     패턴 합성       - 같은 선택을 한 다른 팀들의 사후 신호를 찾는다
     메타인지        - 이 결정이 실제로는 조직 문제인지 되짚는다

4. 예상 비용 (추정치)
   메인에 실릴 팩      ≈ 123K 토큰
   서브에이전트 작업    ≈ 136K 토큰
   ※ 두 값 모두 추정이며 실제와 다를 수 있습니다.

5. 리서치: ON (기본)

6. 조작
   Enter    진행
   숫자     예산 상한 지정 (예: 60000)
   모듈 ±   추가·제거 (예: "메타인지 빼고 유니콘 플레이북 넣어")
   --nosearch  리서치 끄기
```

여기서 `60000`을 입력하면 정해진 순서로 깎는다. 리서치 축소 -> ★ 낮은 모듈 통째 제외 ->
적용 레이어 축약. **모듈을 중간에서 자르지는 않는다.** 원문을 잘라 싣는 순간 팩은 다시 요약본이
되고, 그것이 이 도구가 존재하는 이유를 지운다.

헤드리스로 돌면 게이트가 상한 120K로 자동 진행하고 무엇을 깎았는지 출력에 남긴다.

## 팩이란 무엇인가

팩은 vault 안의 디렉터리 하나이고 파일 두 개를 담는다.

```
{VAULT}/packs/2026-03-14-team-onboarding-redesign/
├── pack.md
└── manifest.json
```

`pack.md`는 항상 아래 6개 절을 이 순서로 갖는다.

| 절 | 내용 |
|---|---|
| 1. 무장 브리핑 | 활성 프레임, 이 작업에 적용할 규칙, 관련 과거 인사이트, 경계할 편향, 다음 단계. 30~50줄. 사용자에게 출력되는 것이 이 절이다 |
| 2. 작업 해석 | 작업 재진술. 주제만 왔으면 예상 작업 3개 |
| 3. 리서치 합성 | 도메인 현황, 수치-출처 짝, 플레이어, 반대 신호 최소 1개, 출처 URL. `--nosearch`이거나 검색이 불가하면 생략 |
| 4. 작업 적용 레이어 | 모듈당 20~40줄. "이 프레임을 이 작업에 이렇게 쓴다". 프레임 간 충돌과 어느 쪽을 언제 따를지 판단 기준 포함 |
| 5. 레퍼런스 원문 | 선택 모듈 전문. 원본 SHA-256을 담은 `MODULE-BEGIN` / `MODULE-END` 마커로 감싼다 |
| 6. 과거 인사이트와 프로필 | 이 작업에 실제로 걸리는 인사이트와 프로필 항목만 |

`manifest.json`에는 작업, 해석, Cynefin 도메인, 분류, 모듈, 예산, 리서치 여부, 프로필 버전,
토큰 추정치, 생성 시각, 런타임이 기록된다. 팩은 20개까지 보관하고, 넘으면 어느 것이
오래됐는지 알려주되 **삭제는 사용자가 정한다.** `--pack`으로 재장전할 수 있는 자산이라
자동으로 지우지 않는다.

## 진화

SmartThink는 3층으로 사용자에게 맞춰 간다.

| 층 | 담는 것 | 쓰는 주체 |
|---|---|---|
| 프로필 | 정체성, 현재 목표, 스타일, 기본값, 소스, 이력 요약 | `/st init`, 그리고 사용자. 직접 편집하라고 만든 파일이다 |
| 라우팅 가중치·인사이트·갭 | 어떤 사고 유형에 어떤 모듈이 실제로 먹혔는지, 인사이트 10슬롯과 갭 5슬롯 | `/st retain`. 승인된 것만 |
| 팩 캐시 | 만들어진 모든 팩. `--pack`으로 재장전 | 매 무장 |

- **`/st init`**은 로컬만 스캔하고(프로젝트 루트 지침 파일, `~/.claude`, git log 50건, 지정한
  노트 디렉터리) 추정 결과를 먼저 보여준 뒤, 전부 건너뛸 수 있는 6개 질문을 하고 프로필을
  쓴다. 읽기만 하며 외부로 아무것도 전송하지 않는다.
- **`/st retain`**은 어떤 프레임이 실제로 판단을 바꿨고 어떤 것이 로딩만 되고 기여하지
  않았는지 가려낸 뒤, 세 덩어리로 나눠 제안한다. 라우팅 가중치 델타, 인사이트·갭 변경,
  프로필 델타. 각각 따로 수락·거부·수정할 수 있고, 승인 없이는 아무것도 쓰지 않는다.
- **`/st status`**는 프로필 요약, 최근 팩 5개, 진화 카운트, 환경 진단을 보여주고 문제마다
  무엇을 하면 되는지 한 줄씩 붙인다. 아무것도 쓰지 않는다.

이 전부가 **리포 바깥**에 산다. 기본값은 `~/.claude/smartthink-vault/`이고 `SMARTTHINK_VAULT`나
프로필로 옮길 수 있다. 개인 인사이트가 리포에 커밋되는 일은 없다.

## 환경별 동작 (우아한 축소)

결핍 환경에서의 동작은 즉흥이 아니라 고정돼 있다.

| 결핍 | 동작 |
|---|---|
| Agent 도구 없음(Codex 등) | **인라인 경로**: 메인이 같은 일을 직접 한다. 게이트도, 팩 명세도, vault도 같다. 차이는 레퍼런스 로딩과 리서치가 메인 컨텍스트를 소모한다는 것뿐이고, 게이트가 그 사실을 표시한다 |
| `st-armorer` 정의 없음 | 팩 명세 전문을 브리핑한 general-purpose 에이전트로 폴백, 그것도 안 되면 인라인 경로 |
| `st-thinker` 정의 없음 | `--report`가 동봉된 폴백 프롬프트를 쓴 general-purpose 에이전트로 내려간다 |
| 검색 도구 없음 또는 실패 | 팩 3절 생략, `manifest.research=false`, 브리핑에 명시. 도구 결핍과 사용자가 끈 `--nosearch`는 구분해 표기한다 |
| `insane-search` 스킬 없음 | 일반 fetch만 사용. 차단된 소스는 우회하지 않고 "차단"으로 표기한 뒤 건너뛴다 |
| vault 없음 | 즉석에서 시드 생성. 프로필이 없으면 브리핑에 `/st init` 안내를 붙인다 |
| 진화 상태가 v2 형식 | 읽기는 그대로. 첫 `retain` 때 원본을 백업하고 변환한다 |
| `references/index.json` 없음 | 모듈 크기를 직접 재고, 게이트에 사전 계산값이 아니라 실측 근사임을 표기한다 |
| 대화형 터미널 아님(헤드리스) | 게이트가 상한 120K로 자동 진행하고 무엇을 깎았는지 보고한다 |

## 레퍼런스 모듈

> **레퍼런스 9개는 한국어로 작성돼 있다.** 원문 그대로 실리므로 팩 5절은 인터페이스 언어와
> 무관하게 한국어다. 합성 산출물(브리핑·작업 해석·리서치·적용 레이어)은 프로필에 지정한 언어를
> 따른다. 영어 번역은 알려진 미구현 항목이지 숨겨진 제약이 아니다.

| 모듈 | 역할 |
|---|---|
| 핵심 엔진 | 12개 운영 사고 엔진: 제1원리, 비대칭 기회, 네트워크 효과, 시장 창조, 해자 구축, 반직관 검증, 가치 포착, 타이밍, 복합 우위, 생태계 설계, 역전 사고, 롤라팔루자 |

## 요구사항

- [Claude Code](https://docs.anthropic.com/en/docs/claude-code). 서브에이전트를 지원하면 armorer
  경로를 타고, 없으면 인라인 경로로 같은 팩을 만든다.
- `scripts/build-index.py`와 `scripts/check-structure.py` 실행에 Python 3. 사용에는 필요 없고
  개발에만 필요하다.
- `install.sh`는 macOS 또는 Linux(Windows는 [WSL2](https://learn.microsoft.com/en-us/windows/wsl/)).
  플러그인 경로에는 이 제약이 없다.
- 선택: 일반 fetch를 차단하는 소스를 위한 `insane-search` 스킬. 없으면 해당 소스는 표기하고
  건너뛴다.
- Codex 등 Claude Code가 아닌 하네스는 인라인 경로로 동작할 것으로 보지만 아직 검증되지 않았다.

## 삭제

```bash
cd smartthink
./uninstall.sh
```

심링크만 지우고 vault는 남는다. 완전 초기화는 `~/.claude/smartthink-vault/`를 직접 삭제하면 된다.
