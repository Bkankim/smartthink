## SmartThink 분석: 지역 도서관 예약 안내 개선안 - 어린이 보호자 대상 (v2)

### 핵심 요약 (프레임워크 없는 3줄)
1. 어린이 프로그램 신청에서 보호자가 겪는 문제의 뿌리는 문구가 아니라 **선착순 접속 경쟁 구조**다. 공지에 "F5 새로고침"이 실릴 정도로 규칙의 결함을 안내가 떠안고 있고, 자녀를 돌보며 정해진 시각에 5단계 경로를 통과해야 하는 보호자는 이 구조에서 체계적으로 밀린다. 문구를 고쳐도 경쟁 구조가 남으면 민원은 남는다.
2. 노쇼·결원을 줄인 정량 사례(리에주대 22%→13%)는 성인 좌석 예약에서 자동 취소 규칙으로 얻은 것이고 어린이 프로그램에는 검증된 수치가 하나도 없다. 그러므로 이번 보고서의 모든 기대 효과는 "시범 기준선 대비 -20%"라는 목표치이고, 첫 30일의 일은 개선이 아니라 **기준선을 만드는 것**이다.
3. 권고 순서는 "빼기 → 규칙 → 구조"다. 이번 분기에는 안내에서 범위값·부탁 문장·연령 조문을 빼고 보호자가 할 일과 안 하면 시스템이 할 일을 문장에 넣는다(되돌릴 수 있음). 1개 관에서 노쇼 시 이용정지 대신 다음 회차 우선순위 감점과 결원 자동 승계를 시범한다(8주 후 결원 재배정 소요 시간·노쇼율 -20% 미달이면 중단). 선착순→접수기간+추첨은 1개 강좌 파일럿으로 가장 위험한 가정부터 검증하고, 전면 전환과 가구 단위 계정 통합은 규정·개인정보 검토가 붙는 별도 트랙이다.

### 다층 분석

#### 0. 대상 재정의와 측정 정의 고정

**대상 이용자**: 자녀를 동반해 방문하는 보호자 + 어린이·가족 프로그램을 신청하는 학부모. 조부모 동반은 부분 포함(고령층 조건이 재등장하는 유일한 경로).

**세 영역의 재가중**
- (a) **어린이·가족 프로그램 신청 - 주 영역.** 선착순 경쟁, 다자녀 우선순위, 1인 1강좌, 연령 기준, 취소·노쇼·결원 승계, 보호자 동반 여부 안내.
- (b) **자녀 자료 예약 - 부 영역.** 자녀 계정과 보호자 계정의 관계, 도착 알림 수신자, 상호대차 소요일. 3절 정량 없음.
- (c) **좌석 - 원리 근거 공급원.** 3절에 어린이자료실·가족 공간 좌석 예약 데이터가 없다. 성인 열람실 규칙(죽전 180석·30분 인증)은 보호자가 자녀를 어린이실에 두고 열람실을 쓰는 경우에만 간접 관련. 좌석 데이터는 "이용자는 규칙에 반응하고 리마인더는 한계 효용이 준다"는 원리의 근거로만 쓰고 수치는 이전하지 않는다.

**노쇼 정의(프로그램)**: **노쇼율 = 신청 확정(정원 내) 후 당일 미출석 건수 / 확정 건수.** 보조 지표 ① **결원 재배정 소요 시간**(취소·노쇼 발생 → 대기자 확정까지) ② **결원 잔존율** = (정원 - 실제 출석) / 정원 ③ 접수 관련 문의·민원 건수(유형 태깅). ULiège의 22%→13%는 좌석 점유율의 보수(78→87)로 읽히는 다른 정의이므로 방향만 차용한다. 보호자층에서는 결원 1석이 곧 낙첨된 다른 아동 1명이라 결원 재배정 소요 시간이 노쇼율보다 이용자 체감에 직접 닿는 지표다 - 성공 기준 1순위로 올린다.

**법적 제약의 재평가**: 인권위 2024.2 권고는 **노인** 대상이어서 보호자층에 직접 적용되지 않는다(조부모 동반에만 간접). 형평성 제약은 법적 의무에서 **정책·민원 리스크**로 강도가 내려간다. 대신 **자녀 개인정보 처리**(가구 계정 통합·형제자매 일괄 신청 시)가 새 법적 검토 항목으로 들어온다.

**(g) 2차 사고 체인(감점·승계·자동 취소 후보 필수)**

#### 5. 교차 엔진 합성

- **제1원리(#1) × 역전(#11)**: "노쇼 페널티 = 이용정지"를 해체하면 정지는 결원을 채우지 못한다(결원 회수는 자동 승계가 한다) - 정지는 억제 기능만 남은 관습이다. "감점이 반드시 실패하려면?"을 걸면 형제 동시 노쇼의 이중 누적이 나온다. 결론: **결원 회수(자동 승계)와 억제(어린이 단위 감점)를 분리하고, 감점 단위를 가구가 아닌 어린이 1명·1회차로 고정**하라. 제1원리만으로는 "정지는 관습", 역전만으로는 "감점은 위험"까지만 간다.
- **인지 무기고(최소 작용 #10 × 메커니즘 디자인 #24) × 실행 속도(문 분류)**: 보호자에게 단계를 **더하는** 개선(가구 계정 등록, 참가 확인)은 개인정보·벤더 검토가 붙는 Type 1이고, 단계를 **빼는** 개선(범위값·부탁 문장·조문 연령 표기 제거, 승계를 직원 전화에서 자동으로)은 즉시 되돌릴 수 있는 Type 2다. 첫 분기 포트폴리오는 빼기 위주여야 한다. 세 모델 중 하나만으로는 이 시간 축 규칙이 나오지 않는다.

1. **문구·화면 무변경 규칙 패치: 어린이 단위 감점 + 결원 자동 승계 + 응답 시한 단일값**

   - 문 분류: Type 2(벤더 설정) / Type 1(운영규정). **1개 관 시범 → 킬 기준**: 8주(최소 2회차) 후 재배정 시간 -50% 및 노쇼율 -20% 모두 미달이면 중단 검토, 다자녀 가구 감점 누적 건수가 증가하면 즉시 중단
   - 틀렸다는 신호: 감점 도입 후 노쇼율은 그대로이고 신청 건수만 준다 → 보호자는 억제에 반응하는 게 아니라 위축되는 것이며, 감점을 빼고 승계만 남긴다

2. **보호자 행동 프레임 안내 템플릿: "자격 / 보호자가 할 것 / 안 하면 시스템이 하는 것"**
   - 설명: 모든 프로그램 안내를 3절 구조로 재작성. 연령은 기준일 포함 학년 병기, 보호자 동반 필수·선택 명시, 신청 단위 명시, 접수 개시 시각·정원·현재 대기 수 표기. 범위값·부탁 문장 0건. 관별 차이는 관명을 붙여 표기.

   - 문 분류: Type 2. **1개 관 시범 → 킬 기준**: 안내문 2종 기간 분할 4주, 문의 -20% 미달이면 문안이 아닌 규칙·구조로 원인 이전
   - 틀렸다는 신호: 문의 유형이 "자격이 뭔가"에서 "왜 떨어졌나"로만 이동 → 안내가 아니라 선착순 구조가 문제

   - 리스크 & 안티프래질: 관별 차이가 이용자층 차이(물리)일 가능성 → 통일 전 관별 신청자 구성 확인
   - 문 분류: Type 1. 프리모텀(F11·F12·F14) + ADR, 결정 기한 2주. **킬 기준**: 통일 후 특정 관 민원 급증 시 그 관만 예외 복원
   - 틀렸다는 신호: 통일 후 특정 관 출석률·만족만 급락 → 그 관의 보호자층이 다른 규칙을 필요로 한다

8. **결정 권한 매트릭스: 문구·게시물·FAQ·접수 개시 시각은 팀 DRI 자율**
   - 설명: 승인 레이어 3단계 이상이면 이것을 첫 결정으로. 접수 개시 시각 변경(보호자 시간 창 조정)까지 팀 자율에 포함.
   - 엔진/모델: 실행 속도 레버 1, 관료적 관성 #68
   - 데이터 근거: 직접 수치 없음(미확정). 프로그램 참가 +5.1% vs 사서 +3.0%로 결정 지연 비용 증가의 간접 근거
   - 실행 가능성: High(내부)
   - 기대 효과: 문구·개시 시각 변경 리드타임 당일화, 시범 실험 횟수 증가
   - 리스크 & 안티프래질: 품질 필터 상실 → 보호자 5~10명 정성 읽기 관찰을 승인 대체 게이트로
   - 문 분류: Type 2(내부). **킬 기준**: 자율 결정 후 문구 오류 민원 증가 시 승인 1단계 복원
   - 틀렸다는 신호: 속도는 올랐는데 문구 오류·민원 증가 → 승인이 실제 품질 필터였다

### Top 3 & 유니콘 평가

(공공 부문이므로 "TAM"은 적용 가능 규모, "해자"는 되돌림 저항·지속성으로 읽는다. 금액 환산은 3절에 근거가 없어 하지 않는다.)

1. **규칙 패치(아이디어 1) + 알림 재배치(3) - "결원을 시스템이 채운다"**
   - 적용 가능 규모: 전국 1,328관(2025)의 프로그램 접수, 1관당 연 참가자 22,366명(2024, 어린이 비중은 3절에 없음). 시범은 1개 관 2회차
   - 해자(지속성): 규칙 데이터에 박힌 감점·승계는 담당자 교체(F11)에 강하다. 문구 개선은 약하다
   - 타이밍: 프로그램 참가 +5.1%·방문 +8.7% vs 사서 +3.0%로 직원 전화 승계의 집행 여력이 매년 준다. 프로필 목표(~2026 Q4 실행 계획) 안에 8주 시범이 들어간다
   - 실행 로드맵: **30일** 노쇼·결원 재배정 시간 정의 문서화, 2~3회차 로그로 기준선, 벤더 설정 항목표, 리마인더 1회 고정 / **90일** Wizard of Oz 2주(직원 수동 감점·승계) → 벤더 설정 자동화 → 8주 측정, 다자녀 감점 누적 모니터링, 킬 판정 / **1년** 2번째 관 재검증 후 확산, 규칙 통일(7) Type 1 결정에 데이터 투입
   - 킬러 가정: "보호자는 감점·응답 시한 규칙에 반응한다"(좌석·대학 원리 외삽). 틀리면 노쇼율 불변·신청 건수 감소로 나타나고, 감점을 빼고 승계만 남긴다. 조기 감지: 1회차 감점 통보 후 재신청율, 승계 응답률
   - 리스크 시나리오: 승계 알림 폭주·응답 시한 병목(확률 높음, 영향 심각) → 미응답 자동 이월; 벤더 미지원(높음, 심각) → Type 1로 승격; 다자녀 이중 감점(중간, 치명) → 단위 고정·증가 시 즉시 중단
   - 바벨: 알림 재배치(즉시 롤백)가 안전 쪽, 감점 규칙(8주 킬 기준)이 공격 쪽. 같은 관에서 동시 착수하지 않는다(간섭)

2. **보호자 행동 프레임 안내(아이디어 2) + 권한 매트릭스(8) - "70% 트랙"**
   - 적용 가능 규모: 프로그램·자료 안내 전부. 1관당 프로그램 참가자 22,366명이 연간 노출 규모
   - 해자: 낮음 → 템플릿을 문서 표준으로 등록하고 권한 매트릭스에 묶어 보강
   - 타이밍: 즉시. 규정·벤더 대기 없이 착수 가능한 유일한 트랙
   - 실행 로드맵: **30일** 승인 레이어 조사, 관별 프로그램 규칙표 1장(연령 기준일·단위·우선·노쇼 처리), 안내문 2종 / **90일** 기간 분할 스모크 4주 + 보호자 5~10명 정성 관찰, 문의 유형 태깅 / **1년** 3영역 템플릿 확정, 규칙 통일 시 안내 1종으로 수렴
   - 킬러 가정: "접수 문의의 주원인이 자격·절차 문구의 불명확성이다." 틀리면 문의가 "왜 떨어졌나"로 이동하고, 그 자체가 C(경쟁 구조)의 근거가 된다. 조기 감지: 스모크 2주차 문의 유형 분포
   - 리스크 시나리오: 벤더 화면 수정 불가(높음, 심각) → 현장 게시물·FAQ·SMS 문안으로 축소; 과잉 단순화로 연령 오해(중간, 관리 가능) → 정성 관찰에서 잡음
   - 옵셔널리티: 결과와 무관하게 문의 유형 분포를 만들어 다른 트랙의 결정 정보를 70%로 끌어올린다

3. **1개 강좌 추첨 파일럿(아이디어 4) - "가장 위험한 가정을 가장 작게"**
   - 적용 가능 규모: 파일럿은 1강좌·1회차. 확산 시 어린이 프로그램 전체(참가자 규모는 1관당 22,366명 중 미확인 비중)
   - 해자: 접수 방식은 규정에 박히면 강하지만, 파일럿 단계에서는 없음(의도적)
   - 타이밍: 공공 추첨 사례 부재(반대 신호 3)가 곧 선점 기회이자 최대 불확실성. RAT 25점으로 가장 먼저 검증해야 할 가정
   - 실행 로드맵: **30일** 경쟁 이력 있는 강좌 1개 선정, 가중 기준(다자녀·미참가) 공개 초안, 비교 대상 선착순 강좌 지정 / **90일** 1회차 접수기간+추첨 실행, 출석률·민원 유형 비교, 낙첨자 문의 태깅 / **1년** 2~3개 강좌 확대 후 전면 전환 여부 Type 1 결정(ADR·프리모텀 F1·F3)
   - 킬러 가정: "보호자는 선착순의 속도 경쟁을 불공정으로 느끼되 추첨 결과에는 승복한다." 틀리면 낙첨 민원이 F5 민원을 대체할 뿐이고, 출석률까지 떨어지면 선착순이 열의 필터였다는 뜻이다. 조기 감지: 첫 회차 낙첨자 문의 유형과 출석률
   - 리스크 시나리오: 출석률 하락(중간, 심각) → 동시 비교로 즉시 판별; 역차별 민원(중간, 심각) → 가중 기준 사전 공개; N 부족(높음, 심각) → 정성 관찰 병행, 1회차 결과로 전면 결정하지 않음
   - 바벨: 10% 실험 트랙에 한정(안전), 성공 시 접수 구조 전체의 선택지가 열림(상방)

### Next Steps
1. **프로그램 노쇼율·결원 재배정 소요 시간 정의 문서화**와 보조 지표(결원 잔존율·감점 누적·문의 유형) 확정. 이번 주. 이것 없이는 어떤 시범도 착수하지 않는다.
2. **최근 2~3회차 신청·확정·출석 로그**(경쟁률·노쇼율·재배정 시간 산출)와 **벤더 설정 가능 항목표**(승계 자동화·응답 시한·감점 필드·문구·개시 시각) 요청.
3. **관별 프로그램 규칙표 1장**(연령 기준일·신청 단위·다자녀 우선·노쇼 처리·접수 개시 시각)과 **승인 레이어 수** 조사. 3단계 이상이면 권한 매트릭스를 첫 결정으로.
4. **리마인더 1회 고정 + 승계 알림 응답 시한 문안** 즉시 적용(Type 2), **안내문 2종 스모크** 설계, **파일럿 강좌 1개 선정**.
5. **킬 기준 문서**: "8주(2회차), 결원 재배정 시간 -50% 및 노쇼율 -20% 모두 미달 시 중단 검토 / 다자녀 가구 감점 누적 증가 시 즉시 중단 / 파일럿 출석률 하락 시 확산 중단 / 킬 후 24시간 내 피벗 검토".
6. **자녀 개인정보 처리 검토 착수**(가구 계정 통합의 Type 1 게이트) - 10% 트랙.
7. 시범 실행 전 점검 체크리스트(★ = 누락 시 치명): ★노쇼·결원 정의와 기준선 2회차 / ★벤더 설정 가능 항목 확인 / ★감점 단위 어린이 1명·1회차 고정 / 관별 규칙표 / 범위값·부탁 문장 0건 / 연령 기준일·학년 병기 / 신청 단위 명시 / 리마인더 1회·승계 응답 시한 명시 / DRI 1인·승인 2단계 이하 / 킬 기준 문서 / 담당자 교체 인수 문서 / 정성 관찰 일정 / ★페널티 후보의 2차 효과 3개 기재 / Type 1 후보의 ADR·프리모텀 첨부(F1·F3·F8) / ★가구 통합 전 개인정보 검토.

### 메타인지 기록
