## 1. 무장 브리핑

**활성 프레임 3**

1. **TRIZ 모순 해결 + IFR** - 이 작업의 중심 프레임. "대기열 안내 화면 개선"을 기능 추가 목록이 아니라 모순(정보를 더 주면 화면이 복잡해진다 / 예상 시간은 구체적이어야 하면서 틀려도 신뢰를 잃지 않아야 한다)으로 다시 쓰고, IFR("이용자가 화면을 보지 않아도 자기 차례를 안다")을 기준점으로 개선안 등급을 매긴다.
2. **제1원리 분해(핵심 엔진 #1)** - 현황 진단 단계의 도구. 현재 화면·정책·시스템에 박힌 "당연한 것" 20개를 뽑아 물리적 제약(좌석 수 유한, 이용 시간은 분포)과 관습(벤더 기본 화면, 선착순 규정, 순번 정수 1개 표시)을 갈라놓는다. 개선안은 관습을 제거한 자리에서 나온다.
3. **역전 사고(핵심 엔진 #11)** - 개선안이 나온 직후, 단계 계획을 짜기 전에 켠다. "이 계획이 확실히 실패하려면?"으로 실패 모드 10개 이상을 카탈로그화하고 상위 5개를 실행 계획의 리스크·대응 절로 옮긴다. 복합 우위 적층(#9)은 보조 프레임으로, 단계의 순서(계측 먼저, 화면 나중)를 정할 때만 쓴다.

**이 작업에 적용할 규칙**

- 개선안을 쓰기 전에 IFR 문장 1개와 모순 문장 2개(기술적 1, 물리적 1)를 먼저 확정하라. 이 셋이 없으면 개선안 작성에 들어가지 마라.
- 가정 목록 20개를 현황 진단의 첫 산출물로 만들고, 각 항목에 "물리 제약 / 관습 / 규정" 태그를 붙여라. 규정은 물리법칙이 아니다 - 바꾸는 비용을 계산해 옆에 적어라.
- 수치는 도서관 자체 로그(예약·취소·노쇼·입퇴실 시각, 안내 문의 건수)에서만 가져와라. 이 팩에는 외부 리서치 수치가 없다. 로그가 없으면 "계측 도입"을 실행 계획 1단계로 두고, 수치 없는 개선안에는 가정임을 표기하라.
- 개선안마다 발명 등급(1~4)을 매기고, 등급 1("순번 글자만 키움")만 남으면 모순 해소가 안 된 것이니 분리 원칙으로 되돌아가라. 타협("정보를 약간만 더")은 해법으로 인정하지 마라.
- 실패 모드 카탈로그는 기술·이용자·직원·조달/벤더·규정·데이터 여섯 축 각각에서 최소 1개씩, 총 10개 이상을 채운 뒤에만 확률×영향 매트릭스로 넘어가라.
- 단계 순서는 플라이휠(로그 계측 → 예상 시간 정확도 → 이용자 신뢰 → 알림 기반 행동 변화 → 노쇼·문의 감소 → 더 좋은 데이터)의 시작점부터 쌓아라. 화면 리디자인이 1단계가 되면 순서가 틀린 것이다.
- 모듈 충돌 처리: 제1원리 4단계(백지 재조합, 기존 방식 참고 금지)는 진단·발산 구간에서만, TRIZ 매트릭스·분리 원칙은 개선안 수렴 구간에서만 따르라. 같은 구간에서 둘을 동시에 켜지 마라.
- 검증 단계의 지표는 역전 1단계에서 정한 성공 기준과 동일해야 한다. 나중에 새 지표를 추가하지 마라.

**관련 과거 인사이트**

없음 (진화 상태 빈 시드: 세션 0, 인사이트 0/10, 갭 0/5).

**경계할 편향**
1. **TRIZ의 화면·기술 해법 편향** - 대기열 안내 문제의 원인이 노쇼 정책, 예약 규정, 직원 운영 규칙에 있을 수 있는데, 모듈이 "화면과 시스템에 적용할 원리"로 답을 끌고 간다.
   회피: 모순 식별 단계에서 악화 파라미터 후보에 #37(경영 난이도/직원 부담)과 #30(외부 요인: 규정·조달)을 반드시 1개씩 올려놓고 검토한 기록을 남긴다.
2. **"화면"으로의 조기 수렴** - 해석이 "안내 화면"으로 좁혀져 있어 알림 채널(문자·푸시), 예약 정책, 좌석 배치 같은 화면 밖 레버가 재조합 후보에서 빠질 수 있다.
   회피: 제1원리 4단계 재조합 후보 3개 중 최소 1개는 화면을 바꾸지 않는 안(정책·알림·운영 변경만)으로 만든다.
3. **리서치 부재 상태의 근거 없는 확신** - 3절이 없다. 공공 도서관 시스템의 현행 기능, 타 도서관 사례, 이용자 불만의 실제 분포를 사전 지식으로 채우면 진단이 오염된다.
   회피: 4절과 본 작업에서 수치·사례를 쓸 때마다 "[가정]" 또는 "[도서관 로그 필요]" 표기를 붙이고, 표기 없는 수치는 삭제한다.
