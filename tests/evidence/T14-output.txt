## 1. 무장 브리핑

**활성 프레임 3**
1. **TRIZ 물리적 모순 분리 원칙** — "좌석 정보는 정확해야 하면서 동시에 프라이버시를 침해하지 않아야 한다"는 물리적 모순. 시간 분리(피크/비피크 다른 granularity), 조건 분리(개인 식별 없는 집계 표시)로 풀 수 있다.
2. **제1원리 분해** — "좌석 안내 = 안내판/앱 UI"라는 표면적 가정을 벗기면, 기저 진실은 "이용자는 자리를 찾는 데 드는 탐색 비용(시간+불확실성)을 최소화하고 싶다"다. 여기서 재조합하면 답은 표지판 개선이 아니라 탐색 비용 자체의 제거일 수 있다.
3. **최소 작용 원리 + 손실 회피** — 사용자는 항상 가장 쉬운 경로를 택하고, "자리를 놓칠지 모른다"는 손실 프레임이 "빈자리가 있다"는 이득 프레임보다 행동을 더 강하게 유도한다. 안내 UX는 단계 수 최소화와 손실 회피 프레이밍을 동시에 설계해야 한다.

**이 작업에 적용할 규칙**
- 모순을 타협("어느 정도 정확하게, 어느 정도 사생활 보호")으로 풀지 말고 분리 원칙으로 완전 해소를 시도할 것 (TRIZ 안티패턴 1).
- 표면적 분해("표지판을 더 크게")가 아니라 진짜 기저 진실("탐색 비용")에서 재조합할 것.
- 좌석 사재기(가방 맡아두기 등)는 죄수의 딜레마 구조 — 메커니즘 디자인(#24)으로 규칙을 역산해야지 이용자의 선의에 기대면 안 됨.
- 다른 산업 전이 질문을 반드시 던질 것: "만약 좌석 배정을 항공사가 설계한다면?", "만약 좌석 안내를 레스토랑 웨이팅리스트 앱이 설계한다면?" (패턴 합성 교차 도메인 전이 기법)

**관련 과거 인사이트** — 없음 (vault 미접근, 프로필 없음)

**경계할 편향 (자기점검)**
- 기술 결정론 함정: "센서/IoT를 달면 해결된다"는 인접 가능 프레임워크의 함정. 기술이 인접해도 예산·프라이버시 문화가 인접하지 않을 수 있음.
- 가용성 편향: 최근 본 "스마트 도서관" 사례에 끌려 그 방식을 무비판적으로 이식하지 말 것 — 이 도서관의 실제 병목(예산? 공간구조? 이용자 행동?)을 먼저 확인.

## 2. 작업 해석
주제만 제공됨 → 예상 작업 A(실시간 현황 시스템)/B(사이니지·동선)/C(정책·규칙) 중 하나 또는 조합. 착수 시 어느 방향인지 먼저 확인이 필요합니다.

## 4. 모듈별 작업 적용 레이어

**핵심 엔진 (제1원리 + 반직관 검증)**
- 제1원리 5단계: 가정 추출("좌석표=벽면 게시판", "관리자가 수동 갱신") → 반증 테스트(관습 vs 물리법칙, 전부 관습) → 재조합(이용자 위치 기반 실시간 정보 + 자동 갱신).
- 반직관 검증: "이용자는 정확한 실시간 정보를 원한다"는 합의 자체를 의심할 것 — 오히려 "적당히 여유 있는 구역"만 알아도 충분한 경우가 많다(과도한 정밀도는 비용 대비 효용 낮음, 로슬리더 아님).

**인지 무기고**
- #10 최소 작용 원리: 좌석 확인 단계 수를 줄이는 게 앱 기능 추가보다 우선.
- #31 손실 회피: "지금 3자리 남음"보다 "5분 내 마감 위험" 프레이밍이 행동을 더 이끔(단, 사재기 유도 부작용 주의).
- #22 죄수의 딜레마 + #24 메커니즘 디자인: 자리 비움 방치(가방만 두고 이탈)를 개인의 선의가 아니라 규칙(예: 자동 타이머 기반 좌석 반납)으로 설계.
- #3 임계 질량: 새 안내 시스템이 효과 있으려면 최소한의 이용자 채택률(예: QR 체크인 비율)을 넘어야 함 — 이하에서는 데이터가 불완전해 오히려 신뢰를 잃음.

**TRIZ**
- 기술적 모순: 정보 정확도↑ vs 설치/운영 비용↑, 개인정보 노출↑. → 매트릭스 관점에서 원리 3(국소적 품질: 구역별로 다른 해상도 적용), 원리 24(중간 매개체: 센서 대신 이용자 셀프 체크인 앱을 매개로), 원리 25(자기 봉사: 이용자가 스스로 체크인/아웃).
- 물리적 모순 분리: 조건 분리(좌석 유형별로 다른 안내 정밀도 — 학습실은 세밀, 열람실은 구역 단위), 시간 분리(피크 시간대만 실시간, 비피크는 정적 안내).
- IFR 지향점: "이용자가 아무 조작 없이 자신에게 맞는 빈자리로 자연스럽게 이동한다" — 여기서 갭이 곧 실행 우선순위.

**패턴 합성 (교차 도메인 전이)**
- 항공권 좌석 선택 UX(좌석맵 + 실시간 상태 색상) 전이 가능성.
- 레스토랑 웨이팅리스트 앱(Table Ready 등)의 "예상 대기시간 + 노쇼 페널티" 구조 전이.
- 코워킹 스페이스 좌석 예약 앱의 "시간제 예약 + 자동 해제" 구조 전이.
- 이상 징후 채굴 관점: 현재 도서관에서 이용자가 "잘못된 방식"으로 자리를 확보하는 행태(가방 맡기, 특정 구석 선호)가 있다면, 그것이 숨겨진 수요(조용함, 콘센트, 채광 등)의 신호일 수 있음 — 개선 전에 먼저 조사할 가치.
