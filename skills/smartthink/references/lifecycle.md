# 생명주기 절차서 (`init` / `retain` / `status`)

SKILL.md가 서브커맨드로 판정했을 때 Read하는 **절차서**다. SKILL.md는 라우팅만 하고, 실제로 무엇을
어떤 순서로 묻고 쓰는지는 이 문서가 정본이다.

**메인 에이전트가 직접 수행한다.** 서브에이전트에 위임하지 마라. 세 서브커맨드 전부 사용자와의
짧은 대화가 본체이고, 잡무 위임으로 얻을 게 없다.

서브커맨드 인식 규칙(첫 토큰 정확 일치)은 SKILL.md 소관이다. 여기서는 이미 판정이 끝난
상태로 시작한다.

---

## 공통 규약

### 정본이 어디 있는가

이 문서는 절차만 정의한다. 아래 셋은 **다른 파일이 정본이고 여기서 재정의하지 않는다.**

| 대상 | 정본 | 이 문서의 역할 |
|---|---|---|
| vault 레이아웃, 팩 보관 규칙, 권한·프라이버시 원칙 | `{SKILL_DIR}/.data/README.md` | 참조만 |
| `profile.md` 6블록 구조와 YAML 헤더 | `{SKILL_DIR}/.data/profile.md` | 그대로 복사해 채움 |
| `evolution-state.md` 스키마, 가중치 증분·감쇠식, `diversity_h` 계산, 슬롯 축출 규칙 | `references/analysis-method.md` Step 5 (B) 머지 프로토콜 | 참조만 |

**수식이나 스키마가 필요하면 그 파일을 Read하라. 여기에 옮겨 적지 마라.** 같은 규칙을 두 곳에
적으면 한쪽만 고쳐질 때 조용히 갈라진다.

### `{VAULT}` 해석

`.data/README.md`와 같은 순서다.

1. `st init`에서 사용자가 지정한 경로 (init 이후에는 `profile.md` 5번 블록에 기록되어 이 값이 정본이 된다)
2. 환경변수 `$SMARTTHINK_VAULT`
3. 기본값 `~/.claude/smartthink-vault`

`profile.md` 자체가 vault 안에 사니까 부트스트랩은 2 -> 3 순으로 후보를 잡아 그 안의 `profile.md`를
읽고, 거기서 다른 경로를 선언하면 그 값으로 다시 해석한다.

### 시드 생성

vault가 없으면 `{SKILL_DIR}/.data/`의 템플릿을 **복사해서** 만든다.

```
mkdir -p {VAULT}/packs
cp {SKILL_DIR}/.data/profile.md          {VAULT}/profile.md          # 없을 때만
cp {SKILL_DIR}/.data/evolution-state.md  {VAULT}/evolution-state.md  # 없을 때만
```

- 이미 있는 파일은 **덮어쓰지 않는다.** 존재 확인이 먼저다.
- **`.data/` 자체를 사용자 상태 저장소로 쓰지 않는다.** 플러그인 디렉터리는 업데이트 때 통째로
  교체될 수 있다. 읽고 쓰는 대상은 언제나 `{VAULT}` 아래의 사본이다.
- 기존에 쓰던 vault(Obsidian 등) 안에 자리를 잡는 경우, 기존 파일·디렉터리를 훼손하지 않고
  `profile.md`와 `packs/`만 추가한다. 이름이 겹치면 덮어쓰지 말고 사용자에게 묻는다.

### 쓰기 실패는 보고한다

권한 거부, 경로 없음, 디스크 문제로 쓰기가 실패하면 **조용히 넘어가지 마라.** 실패한 경로와
원인을 사용자에게 그대로 알리고, 무엇이 기록되지 않았는지 명시하라. 성공한 것처럼 완료 보고를
쓰는 게 최악이다.

읽기는 반대다. 읽기 실패는 관용적으로 처리하고 해당 항목을 건너뛴다.

## init

**목적**: 사전 스캔 + 짧은 인터뷰로 `{VAULT}/profile.md`를 각인한다.

**멱등해야 한다.** `{VAULT}/profile.md`가 이미 있으면 새로 만들지 말고 **갱신 모드**로 들어간다.

- 현재 프로필의 6블록을 먼저 보여준다.
- 인터뷰에서 값이 바뀌는 항목만 `기존 -> 새 값` 형태로 제시하고 승인받는다.
- 승인되지 않은 블록은 손대지 않는다. 전부 거절하면 아무것도 쓰지 않고 종료한다.
- 손으로 편집한 프로필을 존중하라. 사용자가 직접 쓴 값을 스캔 추정값으로 덮지 마라.

### 1. 사전 스캔

범위는 **정확히 아래 목록이다.** 늘리지 마라.

| 대상 | 무엇을 |
|---|---|
| 프로젝트 루트 | `AGENTS.md`, `CLAUDE.md`, `SOUL.md`, `DESIGN.md`, `.claude/` |
| `~/.claude` | `CLAUDE.md`, `MEMORY.md` |
| git | 최근 50건 (`git log --oneline -50`) |
| 노트 디렉터리 | 사용자가 지정했을 때만 |

원칙:

- **로컬 읽기만 한다. 외부로 아무것도 전송하지 않는다.** 스캔 내용을 검색 쿼리나 웹 요청에
  싣지 마라.
- **타 런타임의 설정 디렉터리(`~/.codex` 등)는 스캔 대상이 아니다.** 목록에 없는 경로는 열지 않는다.
- 각 항목이 **없어도 실패하지 않는다.** 파일이 없거나, git 리포가 아니거나, 읽기 권한이 없으면
  그 항목만 건너뛰고 "없음"으로 기록한다.
- 스캔 결과는 **요약으로만** `profile.md`에 남긴다. **원문을 복사해 오지 않는다.** 지침 파일
  전문이나 커밋 메시지 뭉치를 프로필에 붙여넣지 마라. 프로필은 1~2K 토큰 예산이다.

**스캔 결과를 먼저 보여주고 확인받는다.** 이게 게이트 T1의 통과 기준이다. 확인 없이 인터뷰로
넘어가지 마라. 표시 형식은 이 정도면 충분하다.

```
사전 스캔 결과 (로컬 읽기만, 외부 전송 없음)

  프로젝트 루트  ./CLAUDE.md, ./.claude/settings.json     (AGENTS.md·SOUL.md·DESIGN.md 없음)
  ~/.claude      CLAUDE.md, MEMORY.md
  git log 50건   최근 작업은 API 스키마 정리와 테스트 보강에 몰려 있음
  노트 디렉터리  지정 없음

여기서 추정한 것:
  역할     백엔드 개발자 (커밋 대상 파일 대부분이 서버 코드)
  도메인   HTTP API, 스키마 마이그레이션
  언어     한국어 (지침 파일이 한국어)

이대로 인터뷰를 시작할까? 틀린 추정이 있으면 지금 알려줘.
```

### 2. 인터뷰 6문

**정확히 이 6개, 이 순서다.** 문항을 더하거나 빼거나 순서를 바꾸지 마라.

| # | 질문 | 대응 블록 |
|---|---|---|
| ① | 주 도메인 | 1. 정체성 |
| ② | 현재 목표 | 2. 현재 목표 |
| ③ | 작업 스타일 (깊이 vs 속도) | 3. 스타일 |
| ④ | 언어 | 3. 스타일 |
| ⑤ | vault 경로 | 5. 소스 |
| ⑥ | 리서치 기본 여부 | 4. 기본값 |

진행 방식:

- **6문을 한꺼번에 쏟지 마라.** 한 번에 1~2문씩 짧게 묻는다. 프로필 각인은 5분짜리 잡무여야지
  설문지가 되면 안 된다.
- 각 질문에 **사전 스캔에서 추론한 기본 제안값을 붙여** Enter 하나로 수락할 수 있게 한다.
  예: `④ 언어는 한국어로 볼까? (Enter = 수락)`
- **전부 건너뛸 수 있다.** "다 건너뛸게" 같은 신호가 오면 즉시 3단계로 간다.
  개별 건너뛰기도 받는다.
- 건너뛴 항목은 **사전 스캔 추정값**으로 채우거나, 추정할 근거가 없으면 `_(미설정)_`으로 둔다.
  추정값을 넣었으면 완료 보고에서 "추정으로 채움"이라고 표시한다.
- 지어내지 마라. 근거 없는 추정보다 `_(미설정)_`이 낫다. 무장 파이프라인은 미설정 항목을
  조용히 건너뛴다.

**⑤ vault 경로**는 기존 vault가 있으면 그 안 `smartthink/`를 제안하는 규칙을 따른다.

- 기존에 쓰는 vault(Obsidian 등)가 스캔이나 대화에서 확인되면 그 안의 `smartthink/`를 제안한다.
  예: `노트 vault가 ~/notes에 있는데, ~/notes/smartthink를 쓸까? (Enter = 수락)`
- 없으면 기본값 `~/.claude/smartthink-vault`를 제안한다.
- 어느 쪽이든 **기존 vault를 훼손하지 않는다.** `profile.md`와 `packs/`만 추가한다.
- 확정된 경로가 이후 이 세션의 `{VAULT}`다.

### 3. `profile.md` 각인

`{SKILL_DIR}/.data/profile.md`의 **6블록 구조와 YAML 헤더를 그대로 쓴다.**

- **블록 이름을 새로 짓지 마라.** 순서도 그대로다.
  1. 정체성 / 2. 현재 목표 / 3. 스타일 / 4. 기본값 / 5. 소스 / 6. 이력 요약
- YAML 헤더는 `version: 3`, `updated: <ISO 8601>`. `updated`를 갱신하지 않으면 갱신이 아니다.
- 템플릿의 `<!-- 예: ... -->` 주석은 형식 안내다. 값을 채운 자리의 예시 주석은 지워도 되고,
  미설정으로 남긴 자리의 주석은 그대로 둔다.
- 6번 블록(이력 요약)은 스캔에서 얻은 **한 줄 요약**이다. 세부는 `evolution-state.md`의 인사이트
  슬롯이 담당한다.
- 전체를 1~2K 토큰(대략 60~100줄) 이내로 유지한다. 매 무장마다 메인이 통째로 Read한다.

쓰기 전에 최종본을 보여주고 승인받는다. 갱신 모드면 diff만 보여줘도 된다.

### 4. 권한 규칙 제안

`~/.claude/settings.json`에 `Edit(<VAULT>/**)` 허용 규칙을 넣을지 **묻는다.**

```
백그라운드 에이전트가 vault에 팩을 쓸 때 권한 프롬프트가 뜬다.
~/.claude/settings.json에 Edit(~/notes/smartthink/**) 허용 규칙을 넣을까?
거절해도 무장은 그대로 동작하고, 매번 승인 프롬프트가 뜰 뿐이야.
```

- **승인했을 때만 기록한다.** 묻지 않고 쓰는 건 금지다.
- 거절해도 아무 기능이 죽지 않는다는 걸 알려라. 압박하지 마라.

`settings.json`은 **리포 밖 파일이다.** 쓰기 규율:

1. 파일을 먼저 Read한다.
2. **없으면 쓰지 말고 사용자에게 보고하라.** 새로 만들지 마라. 다른 설정이 있어야 할 자리에
   빈 파일을 만들면 사용자가 나중에 원인을 못 찾는다.
3. **JSON 파싱이 깨져 있으면 쓰지 말고 보고하라.** 깨진 파일을 고치려 들지 마라.
4. 쓰기 전 백업을 권장한다: `cp ~/.claude/settings.json ~/.claude/settings.json.bak`
5. **기존 내용을 보존하는 머지여야 한다.** 통째 덮어쓰기 금지. 기존 `permissions.allow` 배열에
   항목 하나를 추가하는 것이고, 다른 키·다른 항목은 한 글자도 건드리지 않는다.
6. 같은 규칙이 이미 있으면 중복 추가하지 말고 "이미 있음"이라고 알린다.

### 5. 완료 보고

아래를 빠짐없이 보고한다.

- 만든(또는 갱신한) 경로: `{VAULT}/profile.md`, `{VAULT}/packs/`, 시드로 만든 `evolution-state.md`
- 채운 블록과 그 출처(인터뷰 답 / 스캔 추정)
- 건너뛴 블록 (`_(미설정)_`으로 남은 것)
- 권한 규칙 설치 여부 (설치 / 거절 / 보고만 하고 미실행 + 그 사유)
- 쓰기 실패가 있었으면 경로와 원인

## retain

**목적**: 메인이 대화 이력에서 추론해 초안을 만들고, 사용자가 확인·수정한 뒤, 진화 상태를
갱신한다.

**자동 쓰기는 승인 후에만 한다.** 추론과 기록 사이에 사람이 반드시 들어간다.

### 1. 추론

이번 세션 이력에서 뽑는다.

| 항목 | 무엇을 |
|---|---|
| 실제로 쓰인 프레임·모듈 | 게이트 추천 목록이 아니라 **실사용 집합**이다. 팩이 있으면 `manifest.json`의 `modules[]`와 대조한다 |
| 먹힌 것 | 판단을 **실제로 바꾼** 프레임. 언급만 된 건 여기 아니다 |
| 안 먹힌 것 | 로딩했지만 결론에 기여하지 않은 것. **갭 후보**다 |

이번 세션의 주제 분류(사고 유형)도 함께 잡는다. 가중치 갱신의 키가 된다.

**이력이 부족하면 지어내지 마라.** 무장 없이 시작한 세션, 다른 작업을 하다 온 세션에서는 뽑을 게
없는 게 정상이다. 그럴 땐 "추론할 근거가 부족하다"고 말하고 사용자에게 직접 입력받아라.
없는 근거로 그럴듯한 초안을 만드는 건 진화 상태 오염이다.

### 2. v2 -> v3 변환 선행

기록 전에 대상 파일 형식을 확인한다. `{VAULT}/evolution-state.md`의 **첫 줄이 `---`가 아니면
v2 산문 형식이다.**

순서를 지켜라.

1. **백업 먼저.** 원본을 `{VAULT}/evolution-state.v2.bak.md`로 복사한다. 파일명은 정확히 이것이다.
2. **백업이 실패하면 변환하지 마라.** 원본 소실이 최악이다. 실패를 보고하고 그 세션의 retain은
   중단한다.
3. 변환한다.
   - `scripts/migrate-evolution.py`가 있으면 **그것을 실행한다.**
     인자 없이 실행하면 dry-run이라 아무것도 쓰지 않는다. 실제 변환은
     `python3 scripts/migrate-evolution.py {VAULT}/evolution-state.md --write`로만 일어난다.
     대상 경로를 생략하면 기본 vault를 잡으므로, 변환 대상이 맞는지 dry-run 출력의 `target:` 줄로 먼저 확인한다.
   - 없으면 사용자에게 알리고 인라인 변환(직접 읽어서 v3 스키마로 다시 쓰기)을 제안한다.
     승인 없이 인라인 변환을 강행하지 마라.
4. 변환 후에도 **파일명 `evolution-state.md`는 그대로 유지한다.** 새 이름을 만들지 마라.
5. 첫 줄이 `---`인데 YAML이 깨져 있으면 변환 대상이 아니다. 헤더를 무시하고 본문을 읽은 뒤,
   쓰기 때 헤더를 재생성하고 "헤더 손상으로 재생성했다"고 1줄 보고한다.

v3 스키마 자체는 `references/analysis-method.md` Step 5의 스키마 절이 정본이다.

### 3. 초안 제시

**3덩어리로 나눠 보여준다.** 통짜로 던지지 마라.

**① 라우팅 가중치 델타**

`routing_weights[<사고유형>][<모듈>]`의 증분을 보여준다. 어떤 사고 유형 아래에서, 어떤 모듈이
얼마나 오르고 내리는지.

```
① 라우팅 가중치  (사고 유형: 제품-전략)
   core-engines        4.20 -> 5.20   (실제로 결론을 바꿈)
   triz-innovation     2.85 -> 3.85   (제약 해소 아이디어의 출처)
   pattern-synthesis   1.60 -> 1.52   (이번 세션 미사용, 감쇠)
```

**② 인사이트 추가·갱신 + 갭 추가·해소**

슬롯 상한은 **인사이트 10 / 갭 5**다. 상한을 넘으면 **무엇을 버리는지 함께 제시한다.**
사용자가 모르는 사이에 슬롯이 사라지면 안 된다.

```
② 인사이트 / 갭
   [추가] 인사이트 8/10 -> 9/10
          "제약 조건을 먼저 세우면 모듈 3개로도 결론이 갈린다"
   [강화] 인사이트 #3 (r2 -> r3)
   [해소] 갭 "정량 근거 부족" -> 이번 세션에서 해결, 슬롯 비움 (3/5 -> 2/5)
```

**③ 프로필 델타 제안**

도메인·목표·스타일·기본값이 관찰과 어긋나면 변경안을 낸다. **승인제다.**

```
③ 프로필 델타 제안
   2. 현재 목표   "API 응답 지연 줄이기" -> "신규 서비스 아키텍처 확정"
                  (최근 세 세션 주제가 전부 후자였음)
   4. 기본값      리서치 ON -> OFF  (매번 --nosearch를 붙였음)
```

관찰과 프로필이 일치하면 ③은 "변경 제안 없음"이라고 쓴다. 억지로 만들지 마라.

### 4. 사용자 확인·수정

**세 덩어리를 개별로 수락·거부·수정할 수 있게 하라.** 통짜 승인만 받지 마라.

```
①만 받고 ②③은 다음에, 같은 식으로 골라도 돼.
문구를 고치고 싶으면 그대로 말해줘.
```

- 수정 요청이 오면 반영한 뒤 그 덩어리만 다시 보여주고 재확인한다.
- 세 덩어리 전부 거절이면 아무것도 쓰지 않고 종료한다. 그것도 정상 종료다.

### 5. 기록

**승인된 것만 쓴다.**

- 가중치 증분·감쇠·가지치기 식, `diversity_h` 계산, 인사이트·갭 시맨틱 머지와 슬롯 축출 규칙,
  신선도 태그 `[s{sessions} r{K}]`, 본문 50줄 검증은 전부
  **`references/analysis-method.md` Step 5 (B) 머지 프로토콜을 따른다.**
  **여기서 수식을 다시 정의하지 마라.** 필요하면 그 파일을 Read하라.
- ③이 승인됐으면 `{VAULT}/profile.md`의 해당 블록만 고친다. 다른 블록은 손대지 않는다.
- 두 파일 모두 YAML 헤더의 `updated`를 ISO 8601로 갱신한다.
- 쓰기 실패는 공통 규약대로 보고한다. 부분 성공이면 무엇이 쓰였고 무엇이 안 쓰였는지 명시한다.

### 6. 완료 보고

- 무엇이 바뀌었는지 **diff 요약** (가중치 / 인사이트·갭 / 프로필, 승인된 덩어리만)
- 축출이 일어났으면 버려진 슬롯과 사유

## status

**목적**: 상태 요약과 환경 진단. **별도 doctor 명령은 없다. status가 진단을 겸한다.**

**읽기 전용이다. 아무것도 쓰지 않는다.** vault 시드 생성도, `updated` 갱신도, 팩 삭제도 하지 않는다.
고칠 게 보이면 **무엇을 하면 되는지 안내만** 하고 사용자가 실행하게 한다.

### 1. 프로필 요약

`{VAULT}/profile.md`의 6블록 중 **채워진 것과 비어 있는 것**을 구분해 보여준다. 값은 한 줄씩만.

- 파일이 없으면 그 사실과 함께 `/st init` 안내를 띄운다. 나머지 항목은 계속 진단한다.

### 2. 최근 팩

`{VAULT}/packs/`의 **최근 5개**를 보여준다. 항목당 날짜 · 슬러그 · 모듈 · 리서치 여부.
모듈과 리서치 여부는 각 팩의 `manifest.json`에서 읽는다(`modules[]`, `research`).

- 총 개수가 **20개를 넘으면 삭제 안내만** 한다. 어떤 팩이 오래됐는지 알려주고 지울지는 사용자가
  정한다. **자동 삭제 금지.** 팩은 `--pack <경로>`로 재장전할 수 있는 자산이다.
- `packs/`가 없거나 비면 "아직 없음"으로 표시한다. 만들지 마라.

### 3. 진화 카운트

`{VAULT}/evolution-state.md`의 **YAML 헤더에서 읽는다**(헤더가 정본, 본문은 사람용 사본).

- `sessions`
- `diversity_h` (하한 1.8. 미만이면 편식 상태라고 1줄 덧붙인다)
- 인사이트 n/10, 갭 n/5
- `routing_weights` 상위 항목 몇 개 (사고 유형별 최고 점수 모듈 정도면 충분하다)

v2 형식(YAML 헤더 없음)이면 그 사실을 표시하고 "첫 `/st retain` 때 백업과 함께 v3로 변환된다"고
알린다. **status에서 변환하지 마라.**

### 4. 환경 진단

각 항목을 **OK / NG와 그 의미 1줄**로 표시한다.

| 항목 | 확인 방법 | NG일 때의 의미 |
|---|---|---|
| 에이전트 정의 `st-armorer` | `agents/st-armorer.md` 존재 | 팩 작성이 general-purpose 폴백 또는 인라인 경로로 내려감 |
| 에이전트 정의 `st-thinker` | `agents/st-thinker.md` 존재 | `--report`가 general-purpose + `thinker-prompt.md` 폴백으로 내려감 |
| Agent 도구 사용 가능 | 현재 세션의 도구 목록 | 인라인 경로로 동작한다. 리서치가 메인 컨텍스트를 소모하고 게이트에 비용이 표시됨 |
